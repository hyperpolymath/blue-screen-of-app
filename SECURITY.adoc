=== Reporting a Vulnerability

We take the security of Blue Screen of App seriously. If you believe you
have found a security vulnerability, please report it to us as described
below.

==== Where to Report

*Please do NOT report security vulnerabilities through public GitHub
issues.*

Instead, please report them via one of these methods:

[arabic]
. *Preferred*: Use GitHub’s private vulnerability reporting feature
. *Email*: Send details to [security contact - update with actual email]
. *Security.txt*: See `+.well-known/security.txt+` for additional
contact methods

==== What to Include

Please include the following information in your report:

* Type of vulnerability (e.g., XSS, injection, authentication bypass)
* Full paths of source file(s) related to the vulnerability
* Location of the affected source code (tag/branch/commit or direct URL)
* Step-by-step instructions to reproduce the issue
* Proof-of-concept or exploit code (if possible)
* Impact of the issue, including how an attacker might exploit it

==== Response Timeline

* *Initial Response*: Within 48 hours
* *Status Update*: Within 7 days
* *Fix Timeline*: Depends on severity
** Critical: 7-14 days
** High: 14-30 days
** Medium: 30-60 days
** Low: 60-90 days

==== What to Expect

[arabic]
. *Acknowledgment*: We’ll confirm receipt of your vulnerability report
. *Investigation*: We’ll investigate and validate the report
. *Resolution*: We’ll develop and test a fix
. *Disclosure*: We’ll coordinate disclosure timing with you
. *Credit*: We’ll credit you in the security advisory (unless you prefer
anonymity)

=== Security Measures

==== Current Security Features

[arabic]
. *Helmet.js*: Security headers (XSS protection, MIME sniffing
prevention)
. *Rate Limiting*: API endpoints limited to 100 requests per 15 minutes
per IP
. *CORS*: Configurable cross-origin resource sharing
. *Input Validation*: All query parameters sanitized
. *Error Handling*: No sensitive information leaked in error responses
. *Dependencies*: Zero npm dependencies, pure Deno
. *Container Security*: Rootless Podman, minimal base image
. *No Secrets*: No hardcoded credentials or API keys

==== Security Best Practices

When using this application:

[arabic]
. *Environment Variables*: Never commit `+.env+` files with secrets
. *HTTPS*: Always use HTTPS in production
. *Updates*: Keep Deno updated (`+deno upgrade+`)
. *Logging*: Review logs regularly for suspicious activity
. *Rate Limiting*: Adjust rate limits based on your traffic patterns
. *CORS*: Restrict origins in production environments

=== Known Security Considerations

==== Non-Issues (By Design)

[arabic]
. *No Authentication*: This is a public demo application
. *Open CORS*: Default allows all origins (configure for production)
. *No Data Storage*: No user data is stored or transmitted
. *Humorous Content*: Error messages are jokes, not real system errors

==== Potential Risks

[arabic]
. *Phishing*: Could be used in social engineering attacks
* *Mitigation*: Clear documentation that this is a demo/joke app
. *Resource Exhaustion*: API calls could consume server resources
* *Mitigation*: Rate limiting enabled by default
. *XSS in Custom Messages*: Custom error messages rendered in HTML
* *Mitigation*: EJS auto-escapes all variables
